01 Triggers

Every way a run starts. One tool to follow it.

Start a workflow by hand, from a webhook, on a cron schedule or from your CI pipeline. SageCode streams each one live, node by node, as it runs on your servers.

MANUAL

Run it now

Run any workflow or script and follow it live. Ctrl+C cancels, and the logs land in your workspace.

$ sagex run workflow Deploy \ -p VERSION=1.4.2
HTTP

Expose a webhook

One command creates an HTTP trigger; trigger poll follows its runs. Every call carries an Idempotency-Key, so retries never run twice.

$ sagex trigger create Deploy \ -t http
CRON

Schedule it

Five-field cron in UTC, validated by the scheduler itself. SageCode shows the next runs, then can wait for one and follow it.

next run in …
$ sagex trigger create Backup \ -t schedule \ --cron "0 2 * * *"
CI/CD

Wire it into CI

Set SAGEX_API_KEY and call SageCode from any pipeline. The exit code follows the run, so a failed deploy fails the build.

$ sagex run workflow Deploy \ -p VERSION=$GITHUB_SHA
02 Version control

Infrastructure as files.

Keep workflows and scripts as plain files in git, next to the code they deploy. Edit them in your own editor; SageCode shows you exactly what changes before anything reaches the server.

  • new scaffolds a workflow or script, with every field explained
  • syntax prints copy-paste JSON for any node or edge
  • render --file previews a workflow's flow before you push
  • push creates or updates, and asks first; scripts show a diff
  • copy pulls workflows, scripts and run logs into your workspace

04 Architecture

Your terminal, a control plane, your servers.

SageCode never connects to your servers itself. It talks to the Autosage API over HTTPS; Autosage validates, queues and executes the work, then streams every line back.

01 / CLIENT

Your terminal

The SageCode CLI or terminal app, authenticated with an API key from your OS keychain.

HTTPS · X-API-Key
02 / CONTROL PLANE

Autosage

Stores workflows, scripts and vaults, checks each run, and owns the webhooks and the scheduler.

REST · queue · cron
03 / EXECUTION

Workers

Fetch the script, fill in its parameters and connect to the target, streaming output as it happens.

SSH · WinRM · SMTP
04 / STREAM

Live output

Every line flows back as server-sent events, to SageCode, the web app, or both at once.

SSE
05 Security

Secrets stay secret.

SageCode handles server passwords, SSH keys and webhook secrets. It's built so none of them end up in your shell history, your workspace or a stray screenshot.

Keychain, not dotfiles

Your API key lives in Credential Manager, Keychain or Secret Service. CI jobs use SAGEX_API_KEY.

Never on the command line

Passwords and keys go in at hidden prompts, or from a file you point to. Never as flags.

Hidden by default

Credentials can't be copied to disk. show key keeps values hidden unless you pass --reveal and confirm.

Shown once

A webhook's secret appears exactly once, when it's created or rotated. The server keeps only a hash.
